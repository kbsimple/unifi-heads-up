## Why Remove Vercel

Discussion in last session concluded Vercel offers limited value for this project:

- App needs LAN access to UniFi console — Vercel can never host the real working app
- Only useful for mock-mode preview deploys, which `./dev.sh` already covers locally
- Mock previews are misleading: they hide the SQLite recorder, traffic history, and LAN-dependency that make the app actually work
- Maintenance cost: `.env.vercel-mock`, dummy `UNIFI_CONSOLE_ID` values, separate mental model
- Minor secrets-hygiene concern: UAT `SESSION_SECRET` published to third-party platform for zero production benefit
- `next.config.ts` has hardcoded LAN IPs in `allowedOrigins` — already not designed for cloud hosting
