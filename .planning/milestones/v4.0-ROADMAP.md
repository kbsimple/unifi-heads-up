## Milestone Summary

**Key Decisions:**

- UNIFI_MOCK=true in webServer.env — in-process mock is the only viable strategy; undici.Agent ignores HTTP_PROXY/HTTPS_PROXY env vars, ruling out MSW and proxy-based approaches
- ADMIN_PASSWORD uses bcrypt hash of 'testpassword' — NODE_ENV=production server rejects DEV_ADMIN_PASSWORD plaintext fallback
- Port 3001 for E2E webServer — avoids collision with dev server on 3000 when reuseExistingServer is true
- baseURL placed in use{} not top-level — TypeScript PlaywrightTestConfig types require it inside use.{}
- Standalone Next.js server — npm run build + cp static assets + node .next/standalone/server.js (npm start incompatible with output: standalone)
- cwd: projectRoot (computed via __dirname) — prevents webServer command paths resolving from e2e/ instead of project root
- Setup project needs explicit testDir: ./fixtures — auth.setup.ts is outside the global testDir ./tests
- Unauthenticated browser.newContext() must pass { storageState: { cookies: [], origins: [] } } — project storageState is inherited otherwise
- Dashboard table selectors: getByRole('cell') for client names, table-scoped [data-slot="badge"] for traffic status badges

**Issues Resolved:**

- baseURL top-level TypeScript error — fixed by moving into use{}
- npm start incompatibility — fixed by switching to node .next/standalone/server.js with static asset copy
- Unauthenticated test inheriting auth cookie — fixed with explicit empty storageState override
- Logout button selector "Log out" vs "Sign out" — corrected to /sign.?out/i
- Dashboard client name ambiguity (card vs table) — fixed with getByRole('cell') selector

**Issues Deferred:**

- No globalSetup to wipe /tmp/e2e-snapshots.db between runs (low impact — current tests don't assert on DB data values)
- Toggle tests would fail on Playwright retry (mutable mock state) — no retries configured; low risk
- FAMILY_USER/FAMILY_PASSWORD configured but no family-role permission tests

**Technical Debt Incurred:**

- Auth file path (`e2e/playwright/.auth/user.json`) hardcoded in two places (auth.setup.ts and playwright.config.ts) — drift risk if paths diverge
