# Milestone v3.0: Statefulness & Insights

**Status:** ✅ SHIPPED 2026-05-17
**Phases:** 8–11
**Total Plans:** 7

## Overview

Added server-side traffic history (SQLite), starred firewall rules, multi-day insights page, and firewall rule scheduling. The app now persists bandwidth snapshots continuously, lets users star and filter firewall rules, visualize which devices consume the most bandwidth, and set time-limited schedules on firewall rules.

## Phases

### Phase 8: SQLite Snapshot Infrastructure

**Goal:** The server continuously records per-client bandwidth into SQLite, independent of any browser session, with automatic 30-day cleanup
**Depends on:** Phase 7
**Plans:** 1 plan

- [x] 08-01-PLAN.md — DB module, recorder singleton, instrumentation hook, and tests

**Key decisions:**
- `better-sqlite3` chosen for synchronous API — simpler background recorder with no async complexity
- `purgeOldSnapshots()` called inline after each insert — no separate cron needed
- `instrumentation.ts` uses dynamic import of recorder to avoid circular init issues at Next.js boot

---

### Phase 9: Starred Firewall Rules

**Goal:** Users can mark firewall rules as favourites from any device, and filter the list to starred rules only
**Depends on:** Phase 7
**Plans:** 1 plan

- [x] 09-01-PLAN.md — SQLite db helper + starred API routes + star UI + filter toggle

**Key decisions:**
- `starred_rules` table added to existing `getDb()` initializer alongside `snapshots` table
- `INSERT OR REPLACE` used for idempotent upsert — prevents duplicate-key errors on double-star
- SWR optimistic mutate with `res.ok` check for HTTP-error revert

---

### Phase 10: Insights Page

**Goal:** Users can explore which devices consume the most bandwidth and when they are typically active, over a user-chosen time window
**Depends on:** Phase 8
**Plans:** 3 plans

- [x] 10-01-PLAN.md — Insights query module (Vitest-tested) + two authenticated API routes
- [x] 10-02-PLAN.md — Nav link + Insights page Server Component shell
- [x] 10-03-PLAN.md — InsightsShell, TopDevicesChart, DeviceActivityHeatmap + page wiring

**Key decisions:**
- SQL adapted to actual schema columns (`client_mac`, `download_bps`, `upload_bps`)
- Native `<select>` used instead of shadcn Select (not available in project)
- Inline CSS grid for 24-column heatmap (Tailwind v4 has no `grid-cols-24`)
- `BarRectangleItem.payload` typed as `any` to access `mac` from Recharts click handler

---

### Phase 11: Firewall Rule Scheduling

**Goal:** Users can set a temporary duration on an enabled firewall rule, after which the rule is automatically disabled
**Depends on:** Phase 3
**Plans:** 2 plans

- [x] 11-01-PLAN.md — Extend types, client, mock, and API routes for native UniFi schedule field
- [x] 11-02-PLAN.md — SchedulePicker + ScheduleBadge components + FirewallCard integration

**Key decisions:**
- `UnifiScheduleSchema` uses `z.union` ALWAYS|ONE_TIME_ONLY with `passthrough()` on ALWAYS
- POST always sets `enabled=true` (scheduling implies enabling)
- DELETE GETs current policies to preserve existing enabled state before writing ALWAYS
- `@base-ui/react` Popover — `PopoverTrigger` has no `asChild`; trigger is native button

## Milestone Summary

**Key Accomplishments:**
1. SQLite snapshot recorder using `better-sqlite3` with 60s interval, 30-day auto-purge, Next.js instrumentation hook

3. Insights page: ranked top-devices bar chart + 24-column hourly heatmap, 7/14/30d range selector
