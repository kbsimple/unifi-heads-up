<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/firewall/starred | Untrusted ruleId and starred values cross from browser to server |
| server → SQLite file | DB_PATH controls where data is written — must be a controlled path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | POST /api/firewall/starred body | mitigate | Zod schema validates ruleId is non-empty string and starred is boolean; rejects other types at route entry |
| T-09-02 | Spoofing | GET and POST starred routes | mitigate | getSession() check before any DB access; returns 401 if no valid session |
| T-09-03 | Elevation | ruleId accepted verbatim as TEXT PRIMARY KEY | accept | No shell interpolation; parameterized better-sqlite3 prepared statement prevents SQL injection |
| T-09-04 | Denial of Service | Unbounded starredIds growth | accept | Personal household use; no rate limiting needed at this scale |
| T-09-05 | Information Disclosure | DB_PATH env var | mitigate | Server-only import guard prevents client bundle from accessing db module; env var not NEXT_PUBLIC_ prefixed |
</threat_model>
