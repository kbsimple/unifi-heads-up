# Quick Task 260609-3e2: Snapshot Average Traffic Status — Complete

## Summary

Dashboard traffic status badges now reflect a rolling average of the last
`SNAPSHOT_WINDOW` (default: 2) snapshots per client rather than a single
instantaneous rate. Eliminates flicker caused by momentary bandwidth spikes.

## Changes

### `src/lib/db/index.ts`
- Added `getRecentAvgRates(macs, window)` — uses a CTE with `ROW_NUMBER() OVER
  (PARTITION BY client_mac ORDER BY recorded_at DESC)` to select the N most recent
  rows per MAC, then averages `download_bps` and `upload_bps` separately. Returns
  a `Map<mac, { avgDownload, avgUpload }>`.

### `src/lib/db/recorder.ts`
- Exported `SNAPSHOT_WINDOW = 2` constant (tune here to adjust sensitivity)
- After `insertSnapshots`, calls `getRecentAvgRates`, re-classifies each client's
  `trafficStatus` via `calculateTrafficStatus(avgDownload, avgUpload)`, then passes
  smoothed clients to `upsertLatestClients`
- Graceful fallback: if a client has no snapshots yet (brand-new device),
  `avgRates.get()` returns `undefined` and the client retains its instant rate

### Tests (+8 new tests)
- `tests/lib/db/db.test.ts`: 6 tests for `getRecentAvgRates` covering empty input,
  correct averaging, window boundary (only N most recent used), single-row client,
  missing-client absence, and multi-client batch
- `tests/lib/db/recorder.test.ts`: 2 new tests — re-classification when averaged
  rates differ from instant rate, and fallback when no avg rates available

## Result

- 319/319 tests pass (was 311 before — +8 new)
- No new TypeScript errors
- `SNAPSHOT_WINDOW = 2` in `recorder.ts` is the single knob to adjust averaging depth
