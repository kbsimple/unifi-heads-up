## Goal

Change the firewall rule toggle UX so the switch is disabled with a visual pending cue while the API call is in flight. Only update the displayed state after the server confirms success. On error, re-enable in original position and show the existing toast.

## Must-Haves

- [ ] Remove optimistic update (`mutate` with `optimisticData`) from `rule-toggle.tsx`
- [ ] Add local `isPending` state (useState) — set true on click, false in finally block
- [ ] Switch is disabled (`disabled={isPending}`) while in flight
- [ ] Visual cue during pending: `opacity-50` or `cursor-not-allowed` on the wrapping element so user knows action is in progress
- [ ] On success: call `mutate('/api/firewall')` with no data arg to trigger SWR revalidation (server is source of truth)
- [ ] On error: toast shown, switch re-enables in original state (no state change since optimistic update is gone)
- [ ] `npx tsc --noEmit` passes
- [ ] Tests in `tests/components/firewall/rule-toggle.test.tsx` updated: remove optimistic assertions, add assertions for disabled state during pending and re-enable after
- [ ] Committed with author Faiser <keepbreakfastsimple@gmail.com>
