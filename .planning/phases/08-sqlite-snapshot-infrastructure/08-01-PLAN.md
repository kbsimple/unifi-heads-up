  <files>src/lib/db/index.ts, tests/lib/db/db.test.ts</files>
  <behavior>
    - getDb() returns the same Database instance on repeated calls (singleton)
    - getDb() creates the data directory and snapshots.db file if they don't exist
    - getDb() creates the snapshots table if it doesn't exist:
        CREATE TABLE IF NOT EXISTS snapshots (
          id INTEGER PRIMARY KEY AUTOINCREMENT,
          client_mac TEXT NOT NULL,
          download_bps INTEGER NOT NULL,
          upload_bps INTEGER NOT NULL,
          recorded_at INTEGER NOT NULL
        )
        CREATE INDEX IF NOT EXISTS idx_recorded_at ON snapshots (recorded_at)
    - insertSnapshots(clients: NetworkClient[]) inserts one row per client with
        client_mac = client.mac, download_bps = Math.round(client.downloadRate),
        upload_bps = Math.round(client.uploadRate), recorded_at = Math.floor(Date.now() / 1000)
    - insertSnapshots() calls purgeOldSnapshots() after writing
    - purgeOldSnapshots() deletes rows where recorded_at < (now_unix - 30 * 24 * 60 * 60)
    - insertSnapshots([]) with empty array is a no-op (no DB calls)
    - DB path: process.env.SQLITE_PATH ?? './data/snapshots.db' (read inside getDb() body)
  </behavior>

  <behavior>
    - startRecorder() starts a setInterval at 60_000 ms
    - startRecorder() called a second time is a no-op (module-level `started` boolean guard)
    - On each tick: calls getUnifiClients(), then insertSnapshots(clients) with the result
    - Errors from getUnifiClients() or insertSnapshots() are caught and logged with console.error
      but do NOT crash the interval (next tick still runs)
    - instrumentation.ts exports an async register() function that calls startRecorder()
      and returns; it guards with `process.env.NEXT_RUNTIME === 'nodejs'` so it only
      runs in the Node.js runtime (not Edge)
  </behavior>
  <action>
    1. Create src/lib/db/recorder.ts:
       - `import 'server-only'`
       - Import `getUnifiClients` from `@/lib/unifi`
       - Import `insertSnapshots` from `@/lib/db`
       - Module-level `let started = false`
       - Export `function startRecorder(): void`:
           if (started) return
           started = true
           setInterval(async () => {
             try {
               const { clients } = await getUnifiClients()
               insertSnapshots(clients)
             } catch (err) {
               console.error('[recorder] snapshot failed', err)
             }
           }, 60_000)

       ```typescript
       export async function register() {
         if (process.env.NEXT_RUNTIME === 'nodejs') {

           startRecorder()
         }
       }
       ```
       Dynamic import (not static) is required here — instrumentation.ts runs before

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UniFi API -> recorder | Data from getUnifiClients() is already validated by Zod schemas in client.ts before reaching recorder |
| SQLite file -> host FS | DB file written to ./data/ — must not be served as a static asset; Docker volume mount isolates it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | snapshots.db file | accept | Local server only; no network exposure of the file; Docker volume not mounted to web root |
| T-08-02 | Denial of Service | setInterval tick | mitigate | try/catch in interval body — exceptions logged but do not crash interval or server |
| T-08-03 | Information Disclosure | SQLITE_PATH env var | accept | Server-only env var, never exposed to client bundle (no NEXT_PUBLIC_ prefix) |
| T-08-04 | Denial of Service | unbounded DB growth | mitigate | purgeOldSnapshots() called on every write cycle — retention enforced at 30 days |
| T-08-05 | Tampering | SQL injection via client_mac | accept | better-sqlite3 prepared statements with positional parameters — no string interpolation in SQL |
</threat_model>
