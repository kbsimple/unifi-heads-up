**Step A: Create e2e/fixtures/auth.setup.ts**

This is the Playwright "setup project" that runs before all other tests. It logs in via the real login form (a Server Action — there is no /api/login route), saves the HTTP-only session cookie to disk, and exits. All subsequent chromium-project tests inherit this auth state.

```typescript
import { test as setup, expect } from '@playwright/test'
import path from 'path'
import fs from 'fs'

const authFile = 'e2e/playwright/.auth/user.json'

setup('authenticate as admin', async ({ page }) => {
  // Ensure the auth directory exists (in case .gitkeep was removed)
  fs.mkdirSync(path.dirname(authFile), { recursive: true })

  await page.goto('/login')
  await page.getByLabel('Username').fill('admin')
  await page.getByLabel('Password').fill('testpassword')
  await page.getByRole('button', { name: 'Sign in' }).click()

  // The login Server Action redirects to /dashboard on success
  await expect(page).toHaveURL('/dashboard')

  // Save ALL cookies (including HTTP-only session cookie) to disk.
  // storageState() captures HTTP-only cookies even though JS cannot access them.
  await page.context().storageState({ path: authFile })
})
```

**Step B: Create e2e/tests/auth.spec.ts**

This file covers the E2E-AUTH requirement: login redirects to /dashboard; unauthenticated access redirects to /login.

```typescript
import { test, expect } from '@playwright/test'

test.describe('Authentication (E2E-AUTH)', () => {
  test('authenticated user reaches /dashboard', async ({ page }) => {
    // The chromium project applies storageState automatically — this page is authenticated
    await page.goto('/dashboard')
    await expect(page).toHaveURL('/dashboard')
    // Verify dashboard content is present (not a redirect placeholder)
    await expect(page.getByText('Network Clients')).toBeVisible()
  })

  test('unauthenticated access to /dashboard redirects to /login', async ({ browser }) => {
    // Create a fresh context WITHOUT storageState — no session cookie is sent
    const context = await browser.newContext()
    const page = await context.newPage()
    await page.goto('/dashboard')
    await expect(page).toHaveURL('/login')
    await context.close()
  })

  test('unauthenticated access to /dashboard/firewall redirects to /login', async ({ browser }) => {
    const context = await browser.newContext()
    const page = await context.newPage()
    await page.goto('/dashboard/firewall')
    await expect(page).toHaveURL('/login')
    await context.close()
  })

  test('logout clears session and redirects to /login', async ({ page }) => {
    await page.goto('/dashboard')
    await expect(page).toHaveURL('/dashboard')
    // Click logout button — use case-insensitive match since button text may vary
    await page.getByRole('button', { name: /log.?out/i }).click()
    await expect(page).toHaveURL('/login')
    // Verify session is cleared: navigating to /dashboard redirects back to /login
    await page.goto('/dashboard')
    await expect(page).toHaveURL('/login')
  })
})
```

NOTES on test design:
- The `page` fixture in the chromium project has `storageState` pre-applied via `playwright.config.ts`. Tests using `{ page }` are already authenticated.
- Tests that need an unauthenticated session use `{ browser }` and create a new context via `browser.newContext()` (no storageState).
- `expect(page).toHaveURL('/login')` auto-waits for the URL to match — handles server-side redirects gracefully.
- The logout test uses `/log.?out/i` regex to match "Log out", "Logout", or "Log Out".

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test config → Next.js server | playwright.config.ts injects credentials into webServer env; these are test-only values and must never be real production secrets |
| browser ↔ Next.js server | Playwright browser sends requests; session cookie is HTTP-only so JS cannot read it; captured by storageState mechanism |
| storageState file → disk | e2e/playwright/.auth/user.json contains a live JWT session cookie; if committed to git it could be replayed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Information Disclosure | `e2e/playwright.config.ts` — ADMIN_PASSWORD in source | accept | Hash (not plaintext) in config; test-only bcrypt hash of 'testpassword' has zero production value; file is committed but contains no real credentials |
| T-12-02 | Information Disclosure | `e2e/playwright/.auth/user.json` — live JWT session cookie | mitigate | Add `e2e/playwright/.auth/user.json` to `.gitignore` (done in Task 1); `.gitkeep` ensures directory exists without committing the cookie file |
| T-12-03 | Spoofing | webServer env — test credentials impersonate real admin | accept | Test server runs on port 3001 with `UNIFI_MOCK=true`; credentials are meaningless outside this isolated server; no real UniFi hardware is affected |
| T-12-04 | Elevation of Privilege | `ADMIN_PASSWORD` bcrypt hash committed in config | accept | Hash of 'testpassword' — a well-known test credential; no real user's password; attacker with the hash still cannot log in to production (different `SESSION_SECRET`) |
| T-12-05 | Denial of Service | `next build` timeout — build takes >180s | mitigate | Set `timeout: 180_000` in webServer config (3 minutes); document in plan that cold builds may exceed 120s |
</threat_model>
