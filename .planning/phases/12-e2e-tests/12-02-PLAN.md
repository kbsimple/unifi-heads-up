**Step B: Create e2e/tests/firewall.spec.ts**

This file covers E2E-FW: the firewall page renders rules and a toggle click changes the enabled state.

Key pattern from `firewall-integration.test.tsx`: the toggle is a `<switch>` role element. Playwright's `getByRole('switch', { name: /Block Gaming Consoles/i })` selects the same element that RTL's `getByRole('switch', { name: /toggle.../i })` selects.

```typescript
import { test, expect } from '@playwright/test'

test.describe('Firewall (E2E-FW)', () => {
  test('renders all three firewall policies from mock data', async ({ page }) => {
    await page.goto('/dashboard/firewall')
    // All 3 mock policies must be visible
    await expect(page.getByText('Block Gaming Consoles')).toBeVisible()
    await expect(page.getByText('Pause Kids Devices')).toBeVisible()
    await expect(page.getByText('Guest Network Restrict')).toBeVisible()
  })

  test('toggle changes enabled state for Block Gaming Consoles', async ({ page }) => {
    await page.goto('/dashboard/firewall')

    // 'Block Gaming Consoles' starts enabled: true in mock data
    const toggle = page.getByRole('switch', { name: /Block Gaming Consoles/i })
    await expect(toggle).toBeChecked()

    // Click to disable
    await toggle.click()

    // UI should reflect disabled state after the SWR mutation resolves
    await expect(toggle).not.toBeChecked()
  })

  test('toggle changes enabled state for Pause Kids Devices', async ({ page }) => {
    await page.goto('/dashboard/firewall')

    // 'Pause Kids Devices' starts enabled: false in mock data
    const toggle = page.getByRole('switch', { name: /Pause Kids Devices/i })
    await expect(toggle).not.toBeChecked()

    // Click to enable
    await toggle.click()

    // UI should reflect enabled state after the SWR mutation resolves
    await expect(toggle).toBeChecked()
  })
})
```

NOTES on toggle test behavior:
- Mock state is module-level in `mock.ts` and resets on server restart. Between tests, the server stays alive (webServer reuse), so toggle state DOES persist between tests in the same run.
- The two toggle tests use different policies to avoid state interference: test 1 disables policy-1, test 2 enables policy-2. These are independent.
- Playwright auto-waits for `expect(toggle).not.toBeChecked()` — it retries until the SWR mutation resolves and React re-renders, up to the default timeout (30s).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js API routes | Playwright browser drives real HTTP requests to /api/firewall; the mock server processes them |
| Next.js API routes → mock.ts | API routes call updateFirewallPolicy() in mock.ts; mock state mutates in-memory during the test run |
| Insights API → SQLite | /api/insights reads from SQLITE_PATH=/tmp/e2e-snapshots.db; empty DB must not crash the endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-06 | Tampering | mock.ts module-level state — toggle state persists across tests in the same server process | accept | Test design avoids interference: toggle tests use different policies (policy-1, policy-2); order-independence is maintained; documented in test comments |
| T-12-07 | Information Disclosure | `/tmp/e2e-snapshots.db` — temp SQLite DB contains test data | accept | Temp file path is not sensitive (UNIFI_MOCK=true means no real user data); file is cleaned by OS on reboot |
| T-12-08 | Denial of Service | Insights page crashes on empty SQLite DB — test fails and blocks CI | mitigate | Insights tests assert page load without data-specific assertions; empty-DB graceful render is the explicit test target per E2E-INSIGHTS scope |
| T-12-09 | Spoofing | storageState cookie replayed outside test environment | accept | Session cookie is signed with `SESSION_SECRET: 'e2e-test-secret-key...'` — useless against a production server with a different secret |
</threat_model>
