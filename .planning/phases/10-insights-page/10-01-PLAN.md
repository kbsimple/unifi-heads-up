  <files>src/lib/insights/queries.ts, src/lib/insights/queries.test.ts</files>
  <behavior>
    - queryTopDevices(db, days: number): returns array of { mac, totalBytes, displayName? } sorted by totalBytes DESC, limited to top 20
    - queryTopDevices with days=7 sums rx_bytes+tx_bytes for snapshots in the last 7*86400 seconds
    - queryDeviceActivity(db, mac, days): returns array of 24 objects { hour: 0-23, avgMbps: number, active: boolean }
    - avgMbps is (avg(rx_bytes)+avg(tx_bytes)) / 1_000_000 for snapshots grouped by strftime('%H') within the period
    - active=true when avgMbps >= 0.5
    - Both functions accept a mock better-sqlite3 db object for testing (dependency injection)
  </behavior>
  <action>
    Create `src/lib/insights/queries.ts` with two exported functions:

    ```typescript
    import type { Database } from 'better-sqlite3'

    export interface TopDevice {
      mac: string
      totalBytes: number
    }

    export interface HourlyBucket {
      hour: number      // 0-23
      avgMbps: number
      active: boolean   // avgMbps >= 0.5
    }

    export function queryTopDevices(db: Database, days: number): TopDevice[]
    export function queryDeviceActivity(db: Database, mac: string, days: number): HourlyBucket[]
    ```

    queryTopDevices SQL:
    ```sql
    SELECT mac,
           SUM(rx_bytes + tx_bytes) AS totalBytes
    FROM snapshots
    WHERE recorded_at >= strftime('%s','now') - (? * 86400)
    GROUP BY mac
    ORDER BY totalBytes DESC
    LIMIT 20
    ```

    queryDeviceActivity SQL:
    ```sql
    SELECT CAST(strftime('%H', datetime(recorded_at, 'unixepoch')) AS INTEGER) AS hour,
           (AVG(rx_bytes) + AVG(tx_bytes)) / 1000000.0 AS avgMbps
    FROM snapshots
    WHERE mac = ?
      AND recorded_at >= strftime('%s','now') - (? * 86400)
    GROUP BY hour
    ORDER BY hour
    ```
    Fill missing hours (0-23) with avgMbps=0, active=false in application code (not SQL) so the caller always receives exactly 24 buckets.

    For tests: use an in-memory better-sqlite3 database — `import Database from 'better-sqlite3'; const db = new Database(':memory:')` — create the snapshots table and seed fixture rows. Do NOT mock the database module; test the real SQL.

    Verify RED (no implementation) → GREEN (implementation passes) cycle.
  </action>

  </verify>
  <done>All tests pass. queryTopDevices returns rows sorted descending. queryDeviceActivity always returns exactly 24 buckets. Active flag true only when avgMbps >= 0.5.</done>

| Boundary | Description |
|----------|-------------|
| Browser → API routes | Unauthenticated requests, untrusted query params |
| API routes → SQLite | Server-side only; no user input reaches raw SQL unparameterised |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Spoofing | Both API routes | mitigate | Session check via `getSession()` before any DB call; returns 401 if absent |
| T-10-02 | Tampering | `days` param | mitigate | Allowlist check — only 7, 14, 30 accepted; 400 on any other value |
| T-10-03 | Information Disclosure | `mac` param in device-activity | mitigate | Session required; mac is not PII but still auth-gated to prevent enumeration |
| T-10-04 | Injection | SQLite queries | mitigate | All user-controlled values (mac, days) passed as parameterised `?` bindings — never interpolated |
| T-10-05 | Denial of Service | Unbounded query range | accept | days is constrained to max 30; LIMIT 20 on top-devices; low-value home network target |
</threat_model>
