## Color

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | `bg-zinc-900` / `--background` dark | Card surface, page background | firewall-card.tsx |
| Secondary (30%) | `bg-zinc-800` / `--card` dark | Card border (`border-zinc-800`), input backgrounds | firewall-card.tsx |
| Accent (10%) | `--primary` (oklch 0.922 dark mode ≈ near-white) | Active duration preset button fill | globals.css dark |
| Scheduled indicator | `text-blue-400` | Clock icon + countdown text when rule has an active schedule | design default |
| Destructive | `--destructive` (oklch 0.704 0.191 22 dark ≈ red-orange) | "Clear schedule" action only | globals.css |

Accent reserved for:
- The currently selected / active duration preset button (filled state)
- The enabled/disabled badge fill (already used by existing Badge component)

Do NOT use accent for:
- The expiry countdown indicator (use `text-blue-400` — communicates time/info, not a primary action)
- Hover states on preset buttons (use `bg-zinc-700` hover)
- The star icon (already uses `text-yellow-400` — do not change)

Second semantic color — blue (`text-blue-400` / `bg-blue-400/10`):
- Reserved exclusively for the schedule-active indicator (clock icon + countdown/expiry text row)
- Communicates "this rule has a time-bounded state" distinct from enabled/disabled and destructive

## Layout: FirewallCard Augmented State

### Card anatomy (augmented — top-down reading order)

```
┌─────────────────────────────────────────────────────────────┐
│  [Rule Name]                    [★] [Badge] [Clock] [Switch] │
│  [Clock icon] Expires at 14:30           ← only if scheduled │
└─────────────────────────────────────────────────────────────┘
```

- Row 1: existing layout unchanged — rule name left, action cluster right
- Row 2 (conditional): only rendered when `policy.scheduleEnd` is a future Unix timestamp
- The clock icon button in the action cluster opens the `SchedulePicker` popover
- Action cluster order (left to right): Star | Badge | Clock | Switch

### SchedulePicker popover anatomy

```
┌────────────────────────────┐
│  Set active duration        │
│  ┌──────┐ ┌──────┐ ┌──────┐│
│  │  2h  │ │  6h  │ │ 24h  ││
│  └──────┘ └──────┘ └──────┘│
│  [Clear schedule]           │  ← only shown if rule has active schedule
└────────────────────────────┘
```

- Popover title: "Set active duration" (14px, weight 500, `text-zinc-100`)
- Preset pills: three `Button` components, `variant="outline"` by default, `variant="default"` for the currently active preset
- "Clear schedule": text-style destructive button (`variant="ghost"`, `text-destructive`), full-width, only rendered if `policy.scheduleEnd` is set
- Popover width: 200px fixed (`w-50`)
- Popover aligns to the right edge of the clock icon button (`align="end"`)

## Interaction Contract

### Duration preset selection

1. User clicks clock icon on a rule card → `SchedulePicker` popover opens
2. User clicks a preset (2h / 6h / 24h):
   a. Clock icon shows pending state (`opacity-50 cursor-not-allowed`) — same pattern as `RuleToggle`
   b. POST `/api/firewall/schedule` with `{ policyId, durationHours }` — executor defines this route
   c. On success: SWR mutates `/api/firewall` to revalidate; popover closes automatically
   d. On error: toast via `sonner` — "Unable to set schedule. Try again." — clock icon re-enables
3. Rule card re-renders with `ScheduleBadge` row visible

### Clear schedule

1. User opens `SchedulePicker` on a rule that has an active schedule
2. "Clear schedule" button is visible
3. Click → same pending/confirm/error pattern as preset selection
4. DELETE `/api/firewall/schedule` with `{ policyId }` — executor defines this route
5. On success: SWR revalidates; `ScheduleBadge` row disappears

### Expiry countdown

- `ScheduleBadge` computes display string from `policy.scheduleEnd` on each render
- Format: "Expires at HH:MM" using `toLocaleTimeString('en-US', { hour: '2-digit', minute: '2-digit' })`
- If `scheduleEnd` is in the past on render (race condition): show "Expired — reload to refresh" and let SWR next poll clean it up
- No live countdown ticker (no `setInterval`) — static display updated on SWR revalidation (60s interval already set)

### Pending / disabled states

- Follow `RuleToggle` pattern exactly: `opacity-50 cursor-not-allowed` on the trigger, `disabled` on interactive children
- Clock icon button: same `disabled` + opacity treatment while API call in flight
- Do not disable the rule's `Switch` during schedule API calls — they are independent operations

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Clock button aria-label (no schedule) | "Set schedule for {rule name}" | Dynamic rule name |
| Clock button aria-label (with schedule) | "Edit schedule for {rule name}" | When scheduleEnd is set |
| Popover heading | "Set active duration" | Always shown, not conditional |
| Preset button labels | "2h" / "6h" / "24h" | Short, no additional text |
| Preset button aria-label | "Enable for 2 hours" / "Enable for 6 hours" / "Enable for 24 hours" | Full-text for screen readers |
| Clear schedule button | "Clear schedule" | Destructive-styled but no confirmation dialog — action is reversible (user can re-set) |
| Expiry indicator (normal) | "Expires at {HH:MM}" | e.g. "Expires at 14:30" |
| Expiry indicator (past) | "Expired — reload to refresh" | Race condition fallback |
| Schedule set success toast | (none) — visual change is sufficient | ScheduleBadge appearing is the confirmation |
| Schedule error toast | "Unable to set schedule. Try again." | Via sonner, same pattern as rule-toggle |
| Clear error toast | "Unable to clear schedule. Try again." | Via sonner |

Empty state: not applicable — scheduling is an augmentation to existing rule cards, not a standalone list. The firewall list's existing empty states are unchanged.

## Accessibility Contract

- Clock icon button: `aria-label` (see copywriting above), `type="button"`, focusable
- Popover: uses Radix UI Popover — keyboard-navigable by default (Tab, Escape closes)
- Preset pills: `aria-pressed` when active; full-text `aria-label` (see above)
- Clear schedule button: `aria-label="Clear schedule for {rule name}"`
- `ScheduleBadge`: rendered as `<p>` or `<div>` with `role="status"` so screen readers announce schedule changes
- Minimum touch target on preset buttons: 44px height (`h-11`)
- Color contrast: `text-blue-400` on `bg-zinc-900` — executor must verify passes WCAG AA (4.5:1); if not, use `text-blue-300`
